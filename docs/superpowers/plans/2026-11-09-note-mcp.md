# Note persistenti tramite MCP — piano di implementazione

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** l'assistente aggiunge, elenca ed elimina note persistenti tramite un server MCP (FastMCP,
stdio), con la conferma dell'eliminazione chiesta dal programma.

**Architecture:** un pacchetto separato `server_note/` (archivio SQLite + server FastMCP) viene
avviato dall'assistente come sottoprocesso stdio. Il modulo `assistente/note_mcp.py` tiene aperta
la sessione MCP in un event loop su un thread dedicato, fa la discovery con
`langchain-mcp-adapters` e restituisce strumenti LangChain **sincroni** che il grafo esistente usa
come l'orologio. Il nodo `strumenti` impara a distinguere gli errori e a chiedere conferma prima
degli strumenti indicati.

**Tech Stack:** Python 3.13, LangGraph, langchain-openai, FastMCP 3.4.11, mcp 1.30.0,
langchain-mcp-adapters 0.3.2, sqlite3 (libreria standard), pytest.

**Spec:** `docs/superpowers/specs/2026-11-09-note-mcp-design.md` (e la specifica di base
`docs/superpowers/specs/2026-10-26-assistente-laboratorio-design.md`).

## Global Constraints

- Dipendenze nuove in `requirements.txt`, esattamente: `fastmcp==3.4.11`, `mcp==1.30.0`,
  `langchain-mcp-adapters==0.3.2`. Verificato il 2026-11-09 in un ambiente di prova: fastmcp 4.x
  richiede `mcp>=2.3`, mentre langchain-mcp-adapters 0.3.2 richiede `mcp<2`; con la terna sopra
  `pip check` è pulito. `mcp` è fissato perché lo importiamo direttamente.
- Grafo e terminale restano sincroni; nessun `async def` fuori da `assistente/note_mcp.py` e
  `server_note/server.py`.
- Nome, descrizione e schema dei tool delle note solo nel server; il client non li riscrive.
- Testo nota: massimo 500 caratteri, non vuoto dopo `strip()`. `list_notes(limit)`: predefinito
  20, ammesso 1–100, ordine per ID crescente. Data di creazione `YYYY-MM-DD HH:MM` nel fuso
  `FUSO_PREDEFINITO` (predefinito `Europe/Rome`).
- Archivio predefinito `dati/note.db`, variabile `PERCORSO_NOTE`; `dati/` in `.gitignore`.
- ID con `AUTOINCREMENT`: un ID eliminato non viene mai riassegnato.
- Server: `stdout` riservato al protocollo; `mcp.run(show_banner=False, log_level="WARNING")`;
  lo stderr del sottoprocesso va nel file `server_note.log`, nella stessa cartella del log
  dell'assistente.
- Testi fissi verso il modello:
  - `"Errore dello strumento: {messaggio}"` (errore restituito dal server);
  - `"Errore di collegamento: {messaggio}"` (server non raggiungibile, chiuso o in timeout);
  - `"Eliminazione annullata dall'utente: nessuna nota è stata eliminata."`.
- Commit: Conventional Commits in italiano, staging selettivo, uno per task; fermarsi dopo ogni
  task e attendere l'utente.
- Comandi da PowerShell nella radice di `repo-lab-llm`, con `.venv` attivo.

## Review Focus

1. Il modello passa `note_id` come stringa (`"3"`): la conferma deve comunque mostrare la nota 3,
   il server deve accettarla o rifiutarla con un errore, mai eliminare un'altra nota → test nel
   Task 5.
2. Due `delete_note` nello stesso messaggio del modello: due conferme separate, ognuna con il suo
   esito → test nel Task 4.
3. Testo con apostrofi, accenti, virgolette e `;` (es. `l'esame d'inglese; DROP TABLE note`):
   salvato e riletto identico → test nel Task 1.
4. Fine input (Ctrl+Z/Ctrl+D) durante la conferma: vale come «no», nessuna eliminazione, nessun
   falso messaggio «impossibile ottenere una risposta dal modello» → test nel Task 5.
5. Server delle note terminato a metà sessione: errore di collegamento al modello, l'orologio
   funziona ancora → test nei Task 3 e 4.

### Task 3: Client MCP sincrono con discovery

**Files:**
- Create: `assistente/note_mcp.py`
- Modify: `assistente/strumenti.py` (aggiungere `ErroreCollegamento`)
- Test: `tests/test_note_mcp.py`

**Interfaces:**
- Consumes: `python -m server_note` (Task 2).
- Produces:
  - `assistente.strumenti.ErroreCollegamento(Exception)`.
  - `class ClientNote(percorso_note: Path, fuso: str, percorso_log_server: Path, timeout: float = 20.0, python: str = sys.executable)`,
    usabile come context manager (`__enter__` apre, `__exit__` chiude).
  - `ClientNote.apri() -> None`: avvia `<python> -m server_note` con `cwd` = radice del
    progetto, ambiente = `os.environ` più `PERCORSO_NOTE` (assoluto) e `FUSO_PREDEFINITO`;
    stderr del server in `percorso_log_server` (append); `initialize()`; discovery con
    `load_mcp_tools`. Fallimento o timeout → `ErroreCollegamento`.
  - `ClientNote.strumenti() -> list[BaseTool]`: un `StructuredTool` sincrono per ogni tool del
    catalogo, con `name`, `description` e `args_schema` presi dal tool scoperto; restituisce il
    testo dei blocchi `text` del risultato, uniti con `"\n"`.
  - `ClientNote.chiama(nome: str, argomenti: dict) -> str`: stessa esecuzione, usata anche dalla
    conferma (Task 5).
  - Errori: errore restituito dal server → `langchain_core.tools.ToolException` (messaggio del
    server); qualsiasi altro errore, timeout incluso, o client chiuso → `ErroreCollegamento`.
  - `ClientNote.chiudi() -> None`: idempotente, senza traceback.
