# Router dell'ambito — piano di implementazione

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Aggiungere al grafo un nodo `router` con output strutturato (`categoria`, `motivo`) che manda le domande d'ufficio all'agente e quelle fuori ambito a un nodo di rifiuto.

**Architecture:** Un nuovo modulo `assistente/router.py` contiene schema, istruzioni, costruzione del router (stesso modello LM Studio, `with_structured_output` con `include_raw=True`), lettura/controllo della decisione e i messaggi fissi. `grafo.py` riceve il router come parametro obbligatorio e aggiunge i nodi `router`, `rifiuto`, `riformula`; il nodo `modello` si rinomina `agente`.

**Tech Stack:** Python, LangGraph 1.2.17, langchain-openai 1.7.2 (nessuna nuova dipendenza).

**Spec:** `docs/superpowers/specs/2026-11-17-router-design.md`

## Global Constraints

- Ambito: solo lavoro d'ufficio (più strumenti esistenti, saluti, seguiti); fuori ambito sport, gossip, fantasia, consigli medici, ricette/cucina e tutto il resto.
- Categorie esatte: `conversazione`, `fuori_ambito`. Nessun'altra.
- Il router non conosce né sceglie strumenti; mai `method="function_calling"`.
- Nessuna nuova dipendenza; niente import diretto di `pydantic`.
- Errori del router diversi dalla risposta illeggibile si propagano come eccezioni.
- Rifiuto e riformula entrano in cronologia con la domanda.
- Terminale, eventi, strumenti, conferme, limite, config e Docker invariati.
- Conventional Commits in italiano; staging selettivo; fermarsi e chiedere all'utente dopo ogni task.

## Review Focus

1. Seguito dopo un uso di strumenti («e a Tokyo?»): il router deve vedere la domanda precedente e la risposta finale, ma non `ToolMessage` né AIMessage con sole chiamate → test `test_router_riceve_solo_testo` (Task 1) e `test_router_vede_la_cronologia` (Task 2).
2. Domanda in ambito dopo un rifiuto: l'agente riceve la cronologia con domanda e rifiuto → `test_dopo_il_rifiuto_l_agente_vede_la_cronologia` (Task 2).
3. `motivo` con a capo o spazi multipli: la riga di log resta una sola riga → `test_motivo_su_una_riga` (Task 1, in `leggi_decisione`).
4. Risposta grezza illeggibile molto lunga: nel WARNING al massimo 200 caratteri → `test_warning_accorcia_la_risposta` (Task 2).
5. Categoria con maiuscole o spazi (`"Conversazione "`): non è un valore ammesso → riformula → `test_categoria_non_esatta` (Task 1).

### Task 1: Modulo `router.py` e router finto

**Files:**
- Create: `assistente/router.py`
- Modify: `tests/finti.py` (aggiungere `RouterFinto`, `decisione`, `illeggibile`)
- Test: `tests/test_router.py`

**Interfaces:**
- Produces (in `assistente/router.py`):
  - `CATEGORIE: tuple[str, str] = ("conversazione", "fuori_ambito")`
  - `SCHEMA_DECISIONE: dict` — `{"name": "decisione_router", "strict": True, "schema": {...}}` con `categoria` (`enum` = CATEGORIE) e `motivo` (`string`), entrambi `required`, `additionalProperties: False`. Questa forma (con `name` e `schema`) è quella che `langchain_openai` passa a LM Studio come `response_format` di tipo `json_schema`.
  - `MESSAGGIO_RIFIUTO = "Mi dispiace, posso aiutarti solo con il lavoro d'ufficio (mail, testi, organizzazione, note, orari, calcoli)."`
  - `MESSAGGIO_RIFORMULA = "Non ho capito bene la richiesta: puoi riformularla?"`
  - `istruzioni_router() -> str`
  - `messaggi_per_router(messaggi: list[AnyMessage]) -> list[AnyMessage]`
  - `leggi_decisione(uscita: dict) -> dict | None` — riceve l'uscita di `with_structured_output(..., include_raw=True)` (`{"raw", "parsed", "parsing_error"}`), restituisce `{"categoria": str, "motivo": str}` oppure `None` se illeggibile.
  - `testo_grezzo(uscita: dict) -> str` — il contenuto di `uscita["raw"]` come stringa (vuota se manca).
  - `crea_router(config: Config) -> Runnable` — `ChatOpenAI(base_url=config.url_server, model=config.modello, api_key="lm-studio").with_structured_output(SCHEMA_DECISIONE, method="json_schema", include_raw=True)`.
- Produces (in `tests/finti.py`):
  - `decisione(categoria: str, motivo: str = "motivo di prova") -> dict` — uscita come quella reale: `raw=AIMessage(json.dumps(...))`, `parsed={...}`, `parsing_error=None`.
  - `illeggibile(testo: str = "non è json") -> dict` — `raw=AIMessage(testo)`, `parsed=None`, `parsing_error=ValueError(...)`.
  - `RouterFinto(risposte: list[dict | BaseException] | None = None)` con `invoke(messaggi) -> dict` e `ricevuti: list[list[BaseMessage]]`. Con `risposte=None` restituisce sempre `decisione("conversazione")`.
